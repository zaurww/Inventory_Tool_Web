НОВЫЙ ФОРМАТ 2 — АЗЕРБАЙДЖАНСКИЙ ЯЗЫК

Веб-страница, сообщения проверки и новые отчёты — на азербайджанском.
Инструкция для сотрудников: README_AZ.txt.
Старые русские и английские книги продолжают читаться.
Новая входная книга использует обычные диапазоны, автофильтры и именованные
диапазоны для списков. Умных таблиц в новой книге и азербайджанских отчётах нет.
Коды, товары, контрагенты и номера документов не переводятся.
В шаблоне, демо, обновлённой входной книге и отчётах обычные строки имеют
компактную высоту 18 пунктов. Строки с длинным текстом увеличиваются по содержимому.
Для уже скачанной книги получите обновлённую копию через расчёт на сайте.

В браузере преобразование выполняется автоматически в памяти. Скачайте
файл *_AZ.xlsx и продолжайте работу именно в нём. Исходник не перезаписывается.
Отдельное преобразование без расчёта:

  .venv\Scripts\python.exe migrate_input.py Inventory_Input.xlsx Inventory_Input_AZ.xlsx

Команда принимает только НОВОЕ имя назначения и отказывается перезаписывать
существующий файл. Скрытый лист _InventoryMeta хранит версию формата и язык;
не редактируйте его. Неизвестная версия останавливает чтение и подготовку кодов.
Старые английские книги сохраняют прежние правила обязательности полей.
Формулы и пользовательские именованные диапазоны в старой книге требуют
отдельной проверки перед автоматическим преобразованием.

Списки и фильтры заранее охватывают минимум 10 000 строк ввода и расширяются
при следующем расчёте. В списках могут быть пустые строки. При выходе за этот
диапазон пересчитайте и скачайте обновлённую книгу; Python читает все строки.
Нельзя сортировать один столбец отдельно. Вставляйте только значения, чтобы
не переносить постороннее оформление из буфера обмена.

Оба файла доступны и на публичном сайте без ожидания загрузки расчётного модуля.

   http://127.0.0.1:8765/ — публикация в интернете для этого не нужна.

Для остановки локального сервера закройте
окно Run_Web_Pilot или нажмите в нём Ctrl+C.

КАК ВВОДИТЬ ДАННЫЕ

Заголовки находятся в строке 6. Данные начинаются со строки 7.
Не меняйте заголовки и не добавляйте промежуточные итоги в журналы.
Звёздочка * обозначает обязательное поле. Дополнительные условия ниже.
Формулы во входных полях запрещены: нужны готовые значения.

Настройки:
  Компания — название компании.
  Начало истории — первый месяц полной истории, с нулевыми остатками.
  Отчёт по месяц включительно — последний месяц отчёта.
  Обе даты должны быть первым числом месяца.

Товары:
  Код товара (SKU), наименование и единица измерения обязательны.
  Один SKU встречается один раз в справочнике. Разные цены и декларации
  не создают новый SKU. В покупках и продажах SKU может повторяться.
  Регистр и крайние пробелы не различаются: ABC и abc — один код.
  Название и единица товара показываются в справочнике и итоговом отчёте,
  автоматических формул подстановки во входных журналах нет.

Контрагенты:
  Внесите поставщиков, покупателей, брокеров и перевозчиков по одному разу.
  В журналах выбирайте названия из справочника. Повтор названия в справочнике
  блокируется без учёта регистра и крайних пробелов.
  Один контрагент может одновременно быть поставщиком и покупателем.

Покупки:
  Вид покупки: Импорт или Местная.
  Номер декларации / e-qaimə:
    импорт — номер таможенной декларации;
    местная покупка — номер elektron-qaimə faktura.
  Один номер повторяется во всех товарных строках соответствующей поставки.
  Не используйте один номер для разных независимых поставок. Если номера
  совпадают, добавьте различающий префикс и используйте его также в расходах.
  Поставщик — продавец товара. Документ — инвойс или e-qaimə.
  Количество всегда положительное.
  Сумма в валюте — сумма ВСЕЙ строки без НДС, не цена единицы.
  Курс к AZN — AZN за единицу валюты; для AZN всегда 1.
  Код строки справа оставьте пустым для новой операции.

Расходы:
  Одна строка — один сбор или услуга. Выберите номер декларации / e-qaimə.
  Укажите вид расхода, контрагента-исполнителя, документ и дату документа.
  Распределение между товарами выполняется по покупной стоимости в AZN.
  Все известные расходы включаются независимо от даты счёта и конца отчёта.
  Поздний расход пересчитывает исходную покупку и следующие месяцы.
  Отрицательная сумма — корректировка уже учтённых расходов.
  Код расхода оставьте пустым для новой операции.

Продажи:
  Операция: Продажа или Списание. Количество всегда положительное.
  Для продажи обязательны покупатель и выручка всей строки в AZN без НДС
  после скидок. Нулевая выручка допустима: введите 0.
  Для списания покупатель необязателен, выручка пустая или 0.
  Код строки оставьте пустым для новой операции.

Возвраты:
  Операция: Покупатель или Поставщик.
  Сначала рассчитайте исходные операции, чтобы им были присвоены коды.
  Затем откройте ввод заново и выберите код исходной строки из списка.
  Код виден в последнем столбце покупки / продажи и в подробном отчёте.
  Возврат покупателя ссылается только на продажу, не на списание.
  Количество всегда положительное.
  Для покупателя обязательна сумма уменьшения выручки, включая 0.
  Для поставщика уменьшение выручки пустое или 0.
  Возвраты по разным исходным строкам вводите раздельно.
  Код самого возврата оставьте пустым.

АВТОМАТИЧЕСКИЕ КОДЫ И РЕЗЕРВНЫЕ КОПИИ

Recalculate.bat сначала заполняет пустые коды только у введённых операций:
P — покупка, S — продажа / списание, E — расход, R — возврат.
Перед сохранением изменённого исходника создаётся точная копия в backups.
Ранее присвоенные коды не меняются после сортировки или повторного запуска.
В старом формате без новых кодов исходная книга не перезаписывается.
В формате 2 режим --prepare-input также обновляет границы списков и фильтров:
книга сохраняется с резервной копией даже без новых кодов. Веб-режим всегда
работает с отдельной скачиваемой копией.
Не меняйте существующие коды и не очищайте их при исправлении операции.
При копировании строки для НОВОЙ операции очистите скопированный код.
Удалённая исходная операция, на которую есть возврат, должна быть исправлена:
программа не подставляет вместо неё другую строку с автоматически выданным кодом.
Ошибки данных могут быть обнаружены уже после присвоения кодов. Отчёт при этом
не обновляется; присвоенные коды остаются в исходнике.

Для чтения без изменения исходника запускайте inventory.py БЕЗ --prepare-input.
В таком режиме у всех операций уже должны быть коды.

ДУБЛИКАТЫ И ПРОВЕРКИ

Ошибка: повтор SKU в справочнике, повтор контрагента в справочнике,
повтор кода строки в одном журнале, неизвестный SKU или контрагент,
возврат раньше исходной операции или сверх её количества / выручки.
Допустимо: повтор SKU в движениях; повтор номера декларации в товарах и расходах;
несколько операций с одним контрагентом.
Если совпали существенные реквизиты операции при разных кодах, в Checks
появляется WARNING. Обе строки включаются в расчёт: проверьте, не внесён ли
документ дважды. Автоматического удаления похожих строк нет.
Проверки Python обязательны даже при наличии выпадающих списков Excel:
вставка из буфера может обойти проверку Excel.

РАСШИРЕНИЕ И СОРТИРОВКА СТАРЫХ УМНЫХ ТАБЛИЦ

Добавляйте строки клавишей Tab из последней ячейки умной таблицы.
Выпадающие списки используют таблицы справочников. При вставке большого блока
убедитесь, что он входит в умную таблицу, иначе новые значения могут не попасть
в список выбора. Проверки и чтение Python работают и за границей таблиц.
Подсказки и проверки ввода Excel настроены до строки 10006; это не ограничение
расчёта. Для большего объёма нужно продлить правила проверки Excel.
Сортируйте всю таблицу, никогда не сортируйте отдельно один столбец.

РАСЧЁТ И ОТЧЁТЫ

Monthly Summary — месячная выручка, себестоимость продаж (COGS), валовая прибыль,
списания и стоимость остатка. Количества разных товаров здесь не суммируются.
Monthly Inventory — месячное движение и остатки каждого товара, Monthly AVCO.
Sales Detail — продажи и возвраты покупателей; возвраты показаны с минусом.
Sales Summary — месяц + SKU + покупатель: нетто-выручка, COGS, прибыль и маржа.
Shipment Cost — товары поставок: базовая стоимость, распределённые расходы,
полная стоимость (Landed Value) и стоимость единицы (Unit Cost).
Shipment Summary — итоги по номеру декларации / e-qaimə, поставщик и вид покупки.
Shipment Expenses — расшифровка всех известных расходов соответствующих поставок:
исполнитель, документ, дата, вид расхода, валюта, курс и сумма в AZN.
Фильтруйте три листа по Shipment ID, чтобы посмотреть одну декларацию.
Write-offs — отдельный реестр списаний.
Checks — ошибки, предупреждения и сообщения о границах периода.
About — время формирования, имя / отпечаток исходника и правила расчёта.

Shipment Cost и Shipment Summary включают поступления только до конца отчёта.
Shipment Expenses показывает все известные расходы этих поставок. Если одна
поставка содержит поступления до и после конца отчёта, часть её расходов
относится к будущим поступлениям; общий расход и распределённая доля в отчёте
в таком случае различаются.

Net COGS = стоимость продаж минус стоимость возвратов покупателей.
Gross Profit = Net Revenue - Net COGS.
Margin % = Gross Profit / Net Revenue; при выручке <= 0 маржа пустая.
Write-off Cost показывается отдельно. Gross Profit Less Write-offs — не чистая
прибыль: административных и других операционных расходов здесь нет.

Monthly AVCO без возвратов:
  (Стоимость начального остатка + Полная стоимость поступлений)
  / (Количество начального остатка + Количество поступлений).
Возврат покупателя прошлой продажи восстанавливается по AVCO исходного месяца.
Возврат продажи текущего месяца оценивается по AVCO этого же месяца и уменьшает
чистое выбытие, не создавая циклического расчёта.
Возврат поставщику удаляет полную исходную стоимость покупки с долей расходов.
Это стоимость выбытия запасов, не сумма денежных расчётов с поставщиком.
Невозмещённые расходы и разницы с кредит-нотой учитываются отдельно в основном
бухгалтерском учёте.

В расчёте используются Decimal и неокруглённые промежуточные значения.
В Excel суммы показаны с 2 знаками, AVCO — с 6. Сумма визуально округлённых
строк может отличаться на копейки от итога по точным значениям.

ОШИБКИ И СОХРАННОСТЬ ДАННЫХ

Отчёт записывается во временный файл и затем заменяется целиком.
При ошибке создаётся Inventory_Report_Checks.xlsx с листом, строкой и причиной.
Предыдущий Inventory_Report.xlsx не обновляется. Всегда проверяйте
Inventory_Report_last_run.txt и время в About. Старый Checks может оставаться:
ориентируйтесь на последний статус запуска.
Если книга открыта в Excel, Windows может запретить сохранение.
Закройте обе книги и повторите запуск. Несохранённые изменения не читаются.
Для ошибки на английском листе старой книги используйте английское имя листа;
в новой книге соответствия: Purchases = Покупки, Expenses = Расходы,
Sales = Продажи, Returns = Возвраты, Products = Товары.
Поздние расходы меняют прошлые результаты. Для исторических снимков сохраняйте
копии отчётов. Автоматические backups исходника создаются только при присвоении
новых кодов; они не заменяют регулярное резервное копирование всех данных.

ГРАНИЦЫ ВЕРСИИ

Один общий склад, валюта учёта AZN, суммы без НДС, история с нулевого остатка.
Все продажи месяца имеют единый AVCO. Дневные отрицательные остатки не
проверяются: контроль выполняется на конец месяца.
Бесплатные поступления с нулевой покупной суммой, производство, перемещения,
частичные уценки и валютная выручка требуют отдельного расширения.
Нет ограничения на 100 SKU или 2027 год. Ограничения — память и вместимость Excel.
Будущие движения не попадают в отчёт, но всё равно проходят проверки.
Расходы по поставкам учитываются все известные.

ПУБЛИКАЦИЯ ВЕБ-ПРИЛОЖЕНИЯ

Версия показана внизу страницы и в листе Məlumat сформированного отчёта.
При каждом обновлении повышаем VERSION в inventory.py, номер в dist/index.html
и версиях инструкций. Сборка проверяет совпадение номера интерфейса и модуля.
Версия в адресах JS/CSS/XLSX обновляет кэш приложения и файлов при выпуске новой версии.

Публичное приложение:
https://zaurww.github.io/Inventory_Tool_Web/
Работаем только в этом репозитории: меняем код, делаем commit, затем git push.
После push в main выполняются тесты Python 3.12 и 3.14.
При успехе только разрешённые файлы из dist автоматически публикуются
на GitHub Pages. При ошибках тестов сайт не обновляется.
Код, инструкции и учебные тесты открыты. Учётные файлы, backups, outputs
и локальные настройки исключены из Git и из публикации.
Второй репозиторий, отдельный deploy key и секрет для синхронизации не нужны.
Сгенерированные dist/py не редактируются и не хранятся в Git:
build_web.py заново копирует проверенные модули перед запуском и публикацией.
